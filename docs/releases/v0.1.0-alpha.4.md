**Unofficial** OpenSSH-style clients (`pi-sh`, `pi-cp`, `pi-sftp`) for Raspberry Pi Connect. Not affiliated with or endorsed by Raspberry Pi or OpenSSH. This is an alpha prerelease: compatibility and runtime verification are incomplete.

A fix release for iSH, on top of v0.1.0-alpha.3.

## Fixed

### Interactive shell on iSH
On iSH, `pi-sh` without a command ended with `experimental command ended without a verified adapter status` and `remote broker cleanup was not confirmed`. iSH's terminal reports 5-bit characters and speed 0, and pi-sh asked the Pi's terminal for the same. A Linux PTY always uses 8-bit characters, so the request failed and the session ended before the shell started. pi-sh now keeps the Pi's own size and speed in that case, as `sshd` ends up doing. With alpha.3, running `stty cs8 38400` on iSH first works around it; alpha.4 does not need it.

### Clearer TLS errors
`web login HTTPS request failed (TLS certificate verification)` now says why: no trusted root certificate (install or update the CA certificates; on Alpine/iSH `apk add --upgrade ca-certificates`), an expired or not-yet-valid certificate (check the date and time), or a name mismatch. Verification is unchanged.

## Installer
On Linux and iSH the installer warns when no system CA certificates are found, since sign-in would fail. iSH's Alpine image may lack them: run `apk add ca-certificates`.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/paologiua/pi-sh/main/install.sh | bash
# or, without curl (iSH):
wget -qO- https://raw.githubusercontent.com/paologiua/pi-sh/main/install.sh | bash -s -- --downloader wget
```

macOS (amd64/arm64), Linux (386/amd64/arm64) and iSH use the installer, which verifies `SHA256SUMS`. On Windows (amd64/arm64), extract the `.exe` files from the archive. Check the build with `pi-sh -V`; it should print `pi-sh_v0.1.0-alpha.4+g` followed by the commit.

## Known limitations
- iSH: login, saved sessions and the interactive shell prompt have been reached on a physical device (with alpha.3 and the `stty` workaround). The alpha.4 binary has not been run on iSH yet. Sustained interactive use, terminal controls, resizing and transfers have not been verified on iSH.
- Saved-session expiry, logout and keyring storage have not yet been run against the real Connect service.
- Native Linux and Windows runtime is unverified.
- No release signatures; only SHA-256 checksums.

See `docs/SSH_COMPATIBILITY.md` for the full compatibility matrix.
