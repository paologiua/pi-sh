**Unofficial** OpenSSH-style clients (`pi-sh`, `pi-cp`, `pi-sftp`) for Raspberry Pi Connect. Not affiliated with or endorsed by Raspberry Pi or OpenSSH. This is an alpha prerelease: compatibility and runtime verification are incomplete.

A small fix release on top of v0.1.0-alpha.2.

## Fixed

### Recursive uploads keep existing directory modes
`pi-cp -r` and `pi-sftp put -r` now follow OpenSSH 10.3: a destination directory that already exists keeps its permissions unless `-p` is given. alpha.2 followed OpenSSH 10.2, which also changed the mode of existing directories (for example with `pi-cp -r src/. existing-dir:`). Directories the copy creates still get the source mode, and `-p` still copies modes and times. Downloads are unchanged.

## Installer
The installer now defaults to v0.1.0-alpha.3. Everything from alpha.2 still applies: iSH launchers in `/usr/local/bin`, cleanup of earlier copies, and wget when curl is missing (`--downloader wget` forces it).

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/paologiua/pi-sh/main/install.sh | bash
# or, without curl:
wget -qO- https://raw.githubusercontent.com/paologiua/pi-sh/main/install.sh | bash -s -- --downloader wget
```

macOS (amd64/arm64), Linux (386/amd64/arm64) and iSH use the installer, which verifies `SHA256SUMS`. On Windows (amd64/arm64), extract the `.exe` files from the archive. Check the build with `pi-sh -V`; it should print `pi-sh_v0.1.0-alpha.3+g` followed by the commit.

## Known limitations
- The new directory-mode rule is tested against local OpenSSH `scp`; it has not yet been re-run against the real Raspberry Pi.
- Saved sessions have not yet been run against the real Connect service.
- iSH: one non-TTY command has been verified on a physical device. The interactive shell, transfers, and the installer launchers and cleanup have not been verified on iSH yet.
- Native Linux and Windows runtime is unverified.
- No release signatures; only SHA-256 checksums.

See `docs/SSH_COMPATIBILITY.md` for the full compatibility matrix.
